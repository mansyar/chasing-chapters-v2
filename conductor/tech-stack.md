# Technology Stack

| Layer | Technology |
|---|---|
| Framework | Next.js 16.4 (stable) App Router, standalone build (webpack), server-rendered hero (no `ssr:false` above the fold), next/image optimizer cache 24h |
| CMS | Payload CMS 3.90 (local API, Postgres adapter, drafts/versions, localization en/id) |
| i18n | Hand-rolled path-based locales (`/en`, `/id`) - typed dictionaries in `src/lib/i18n/` (`en` is the key source of truth, `id` typed over it; key-parity and source-scan tests), `src/proxy.ts` redirects unprefixed paths (307) and legacy `?locale=` (308), per-page canonical/hreflang/`og:locale` in `src/lib/seo/metadata.ts`, sitemap alternates (`src/lib/seo/sitemap.ts`), a feed per locale, and a remembered `NEXT_LOCALE` cookie written only by the language control; no i18n dependency (added 2026-10-24) |
| Language | TypeScript 7 (`bun check` — Bun-native type checker, TS7 behavior) |
| Runtime/Package Manager | Bun (runtime, package manager, test runner, type checking) |
| Database | PostgreSQL 16 (drizzle-orm 0.45, schema managed via migrations) |
| Cache | Redis (ioredis 6) - translation cache, rate limiting, per-review translation locks, and the rolling translation character budget |
| Comment Moderation | Shared decision module `src/lib/comment-moderation.ts` (`resolveCommentStatus`: banned → rejected, spam-flagged → pending, trusted bypass → approved) built on blocklist heuristics; persisted `spamSignals` field on comments (migration `20261009_195737_add_spam_signals_to_comments`); admin dashboard moderation widget backed by lean `src/lib/moderation-summary.ts` + admin-only `src/app/actions/moderation.ts`, and it revalidates the review's locale paths after a status change so an approval is visible immediately rather than after the ISR window (added 2026-10-10, revalidation added 2026-10-26) |
| Access Control | Payload access rules as the single statement of who may do what. `Authors.role` and `Comments.status` carry field-level `access.update` limited to admins, because the collection-level rules legitimately let a writer edit their own document and would otherwise carry a privileged field with it. `Commenters` and `Comments` deny anonymous `create`; guest commenting does not need either rule open because `submitComment` writes through the Local API where `overrideAccess` defaults to `true`. `ReadingLists.read` follows the `Reviews` shape (admin all, writer own, public constrained to published) since `versions.drafts` is on. Public writes are gated by `canAcceptPublicWrite` from `src/lib/publish-visibility.ts`, the same predicate the public reads use, so a write a reader can make always agrees with what a reader can see; `reportComment` builds its update from report-owned fields only, never spreading the request (added 2026-10-26) |
| Styling | Tailwind CSS 4 (latest), shadcn/ui + Radix (latest), tw-animate-css, sonner (toasts, added 2026-10-08); `@tailwindcss/typography` (devDependency, registered with `@plugin` in `src/app/globals.css`) themed to the site tokens through a `@utility prose-teal` that maps all 36 `--tw-prose-*` variables - base and invert - onto `:root`/`.dark` tokens, so `prose` follows the theme instead of shipping its own grey palette; three semantic colour tokens (`positive`/`warning`/`info`) in `:root` and `.dark` exposed via `@theme inline` back the structured review sections; code blocks use one mode-stable `--muted`/`--foreground` pair instead of the plugin's inverting default, so a `pre` is a panel in both themes; content cards share one `CardLink` base and `ReadingListCard` takes a `sizes` prop so each surface declares the grid its covers land in (added 2026-10-26) |
| Media | Cloudflare R2 (S3 adapter, latest), sharp (blurDataURL, resized variants); public covers served straight from the R2 bucket domain via `src/lib/media-url.ts` + `NEXT_PUBLIC_R2_PUBLIC_URL` (added 2026-10-09), admin uploads still proxy through `/api/media/file`; the storage adapter is selectable (`STORAGE_ADAPTER`: `s3` default, `local` = Payload's own disk storage, used by the e2e run) (added 2026-10-22) |
| Translation | Google Cloud Translation API v10 (v2 Basic client) - requests packed by character count (`TRANSLATION_BATCH_CHAR_TARGET` 5,000 / `TRANSLATION_BATCH_CHAR_CAP` 25,000) rather than by string count, paced by a rolling 100-second character budget (`src/lib/translation-budget.ts`, Redis `INCRBY` on time-bucketed keys with an in-process fallback, limit from `TRANSLATION_CHAR_BUDGET`, default 100,000) so the provider's per-user quota cannot be saturated; a quota response is classified and **not retried** (the retry ladder cannot outlive a 100-second window), attempt failures log structured fields instead of the raw provider error, and a budget stop is persisted with the reason of the limit that actually fired (character budget vs. run deadline) so throttling is distinguishable from a timeout; the admin attention bell breaks failures down by kind (added 2026-10-25, budget-stop attribution corrected 2026-10-26) |
| Monitoring | Sentry 11 (`withSentryConfig` from `@sentry/nextjs/config`, `dataCollection` replaces `sendDefaultPii`), Umami analytics; route error boundaries (`global-error`, `[locale]/error`) report caught errors with route/locale extra via a never-throwing reporter (added 2026-10-27) |
| Validation | Zod 4.6 |
| Testing | Bun test (unit), Playwright (e2e, chromium) — the e2e suite runs against a **production build** (the standalone artifact on port 3100) with a deterministic, idempotent fixture, an offline translation stub and a bounded worker count (3 by default, `PLAYWRIGHT_WORKERS` override, 1 in CI); the run has **a database of its own** (`<DATABASE_URI database name>_e2e`, created and seeded by `src/scripts/e2e-run.ts`), stores its media on the local disk (`STORAGE_ADAPTER=local`) and fails fast when Redis is unreachable; test-only routes 404 unless the harness sets `E2E_TEST_ROUTES=1` (added 2026-10-22, test-route flag 2026-10-27) |
| Lint/Format | Biome 2.5 (migrated from ESLint), husky pre-commit (bun check + biome + bun test) |
| Deploy | Docker (bun alpine, standalone, non-root) → Docker Hub → Coolify (GitHub Actions); PR validation CI via `.github/workflows/ci.yml` (typecheck, lint, test, build against Postgres service; required check on main, added 2026-10-21; plus a sibling e2e job running the Playwright suite against a production build with Postgres + Redis services, added 2026-10-22; plus a sibling `Docker Build` job building the production image against a migrated Postgres, added 2026-10-25 after four deploys failed on a `.dockerignore` exclusion no check covered); `deploy.yml` runs `migrate` → `build-and-push` → `deploy` → `verify` inside a `deploy-production` concurrency group, where `verify` smoke-checks the live origin and fails the run on a non-200; migrations that drop or rename structure in `up()` must carry a `// destructive: <why>` marker enforced by `src/migrations/__tests__/destructive-markers.test.ts`; recovery procedure in `docs/DEPLOYMENT.md`; boot warm-up via `src/instrumentation.ts` → `src/lib/warm-up.ts` (ISR pages warmed on start, added 2026-10-08) |
